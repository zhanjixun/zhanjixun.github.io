# RocketMQ和Kafka的区别

RocketMQ 和 Kafka 是目前工业界最常用的两种消息中间件。虽然它们在架构上有很多相似之处（如分区、顺序写盘），但其设计初衷不同：**Kafka 诞生于日志处理，追求极致吞吐；RocketMQ 诞生于电商交易，追求金融级可靠性和业务特性。**

以下是它们在 2025 年主流版本中的核心区别：

------

### 1. 核心架构与性能对比

| **特性**           | **RocketMQ**                                                 | **Kafka**                                                    |
| ------------------ | ------------------------------------------------------------ | ------------------------------------------------------------ |
| **设计目标**       | 金融级可靠性、丰富的业务功能                                 | 极致的吞吐量、实时流处理                                     |
| **单机吞吐量**     | 十万级                                                       | 百万级                                                       |
| **Topic 支撑数量** | **极高 (几万个)**。所有消息存入同一个 CommitLog，Topic 增多对性能影响小。 | **较低 (几百到几千)**。每个 Partition 对应一个物理文件，Topic 越多，随机 IO 越多，性能下降剧烈。 |
| **存储模型**       | 聚合存储：CommitLog (存储数据) + ConsumeQueue (索引)         | 分散存储：直接按 Partition 存储为物理文件                    |
| **零拷贝技术**     | 主要使用 `mmap`，适合小块数据读取                            | 主要使用 `sendfile`，适合大块数据连续传输                    |

------

### 2. 业务功能差异（RocketMQ 的优势）

RocketMQ 在业务场景下的功能远比 Kafka 丰富：

- **延迟消息：** RocketMQ 原生支持延迟消息（开源版支持 18 个等级，5.x 支持任意秒级延迟）。Kafka 需通过外部插件或自己写逻辑实现。
- **事务消息：** RocketMQ 支持**分布式事务消息**，通过二阶段提交保证本地事务与消息发送的最终一致性。Kafka 虽有事务 API，但主要用于 Stream 流计算中的“精确一次”处理。
- **死信队列 (DLQ)：** RocketMQ 内置死信队列，消费失败的消息会自动进入重试队列或死信队列。Kafka 需要开发者手动实现该逻辑。
- **消息过滤：** RocketMQ 支持在 Broker 端通过 **SQL92** 语法过滤消息。Kafka 通常需要在 Consumer 端拉取后自行过滤。

------

### 3. 数据可靠性与可用性

- **刷盘机制：** RocketMQ 支持**同步刷盘**（消息落盘才返回成功），能保证单机宕机数据零丢失；Kafka 主要是异步刷盘。
- **复制模式：** 两者都支持同步/异步复制。但在同步模式下，RocketMQ 对金融级场景的适配更成熟。
- **高可用架构：**
  - **Kafka：** 原生依赖 ZooKeeper，现在正全面转向 **KRaft** 模式。
  - **RocketMQ：** 使用轻量级的 **NameServer**，架构更简单，且 NameServer 节点间互不通信，可靠性极高。

------

### 4. 总结：该如何选择？

#### **选择 RocketMQ 的场景：**

1. **金融/业务逻辑：** 如订单处理、支付通知，需要事务、延迟消息等特性。
2. **微服务架构：** 复杂的业务解耦，需要支持海量的 Topic。
3. **高一致性要求：** 绝对不能接受消息丢失。

#### **选择 Kafka 的场景：**

1. **大数据处理：** 日志采集、监控指标、用户行为追踪等，追求极致吞吐。
2. **流式计算：** 配合 Flink、Spark Streaming 进行实时数据处理（Kafka Streams 是其原生优势）。
3. **生态融合：** Kafka 在大数据生态圈（Hadoop, ELK 等）的插件和集成度是业界第一。
