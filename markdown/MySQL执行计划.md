# MySQL的执行计划

![](..\assets\images\036ea3ed5070aa0f.jpg)

MySQL 的执行计划是数据库优化器生成的、用于执行一条 SQL 语句的详细步骤和策略。通过分析执行计划，开发者可以了解 MySQL 如何访问数据（如使用索引、全表扫描等），从而优化查询性能。执行计划通常通过 `EXPLAIN` 命令查看。执行计划共有12个字段，以下是字段说明：

| 字段          | 说明                                                         |
| ------------- | ------------------------------------------------------------ |
| id            | 查询的序列号，表示执行顺序（id 相同按顺序执行，id 越大优先级越高） |
| select_type   | 查询类型主要用来说明查询的类型：普通查询、联合查询、子查询等 |
| table         | 表示查询数据所在的表                                         |
| partitions    | 匹配的分区（如果表有分区）                                   |
| **type**      | 访问类型，性能关键指标：  <br/>`system` 表只有一行数据（系统表）<br/> `const` 通过主键或唯一索引直接找到一行（如 WHERE id = 1）<br/> `eq_ref`	联表查询时，使用主键或唯一索引匹配<br/> `ref`使用非唯一索引查找 <br/> `rang`索引范围扫描（如 BETWEEN、IN、>）<br/> `index`全索引扫描（遍历索引树）<br/> `ALL` 全表扫描 |
| possible_keys | 可能使用的索引                                               |
| **key**       | 实际使用的索引，如果为NULL，表示没有用到索引                 |
| key_len       | 使用的索引长度（字节数）                                     |
| ref           | 哪些列或常量被用来与索引比较                                 |
| **rows**      | 预估需要扫描的行数（越小越好）                               |
| filtered      | 查询条件过滤后剩余行的百分比                                 |
| **Extra**     | 额外信息：<br/>Using where：需在存储引擎层过滤数据<br/>Using index：仅通过索引即可获取数据（覆盖索引）<br/>Using temporary：使用了临时表（常见于 GROUP BY、ORDER BY）<br/>Using filesort：需额外排序（可能影响性能）<br/>Using join buffer：使用了连接缓存（联表查询较多时需注意） |

重点关注 `type`、`key`、`rows` 和 `Extra` 字段

优化目标：减少全表扫描、利用覆盖索引、避免临时表和额外排序
