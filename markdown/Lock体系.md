# Lock体系

`Lock` 提供了比 `synchronized` 更细粒度的线程控制，适用于需要高级同步策略的复杂并发场景。

```java
Lock lock = new ReentrantLock();
lock.lock();
try {
    // 临界区代码
} finally {
    lock.unlock(); // 确保锁被释放
}
```

## 作用

### 显式控制锁的获取和释放

`Lock` 需要手动调用 `lock()` 获取锁，并在 `finally` 块中调用 `unlock()` 释放锁，避免因异常导致的锁泄漏。

### 非阻塞尝试获取锁

`tryLock()`：尝试立即获取锁，失败时不会阻塞线程，直接返回 `boolean` 结果。

`tryLock(long time, TimeUnit unit)`：在指定时间内尝试获取锁，超时后放弃。

## 常见锁

### ReentrantLock 可重入锁

#### 特性

- **独占锁**：同一时间只允许一个线程持有锁
- **可重入性**：同一个线程可以重复获取锁（重入计数机制）
- **公平性**：支持公平锁（按请求顺序分配）和非公平锁（默认，性能更高）

#### 适用场景

- 需要显式控制锁的获取和释放
- 需要可重入的独占锁，且需支持公平性配置

### ReentrantReadWriteLock 读写锁

#### 核心特性

- **读写分离**：通过 `ReadLock`（共享锁）和 `WriteLock`（独占锁）分离读/写操作
  - 读锁：允许多个线程同时读，但排斥写锁
  - 写锁：独占锁，排斥其他所有读锁和写锁
- **可重入性**：读锁和写锁均支持可重入
- **公平性**：支持公平/非公平模式（默认非公平）

#### 适用场景

- **读多写少**的高并发场景（如缓存、配置管理）
- 需要优化读操作的并发性能
