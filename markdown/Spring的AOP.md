# Spring AOP

Spring AOP（面向切面编程）是 Spring 框架的核心特性之一。它通过将那些与业务无关，却为业务模块所共同调用的逻辑（如日志管理、事务控制、权限校验等）封装起来，达到**解耦**和**代码复用**的目的。

以下是 Spring AOP 的核心知识点总结：

## 核心概念（术语）

理解 AOP 的第一步是搞清楚这些容易混淆的术语：

- **Aspect（切面）**：核心模块。它将横切关注点（如日志）模块化。
- **Join Point（连接点）**：程序执行过程中的某个特定点，比如方法调用、异常抛出。在 Spring AOP 中，连接点**仅指方法执行**。
- **Pointcut（切点）**：用于匹配连接点的表达式。它决定了切面代码应该在哪些方法上执行。
- **Advice（通知/增强）**：切面在特定连接点执行的操作。简单说就是“什么时候干什么”。
- **Target Object（目标对象）**：被代理的对象。
- **Proxy（代理）**：AOP 框架创建的对象，用于实现切面契约。
- **Weaving（织入）**：将切面应用到目标对象并创建代理对象的过程。

## 通知类型（Advice）

Spring 定义了五种通知类型，涵盖了方法执行的全生命周期：

| **通知类型** | **注解**          | **执行时机**                                     |
| ------------ | ----------------- | ------------------------------------------------ |
| **前置通知** | `@Before`         | 目标方法调用之前执行                             |
| **后置通知** | `@After`          | 目标方法完成之后执行（无论成功与否）             |
| **返回通知** | `@AfterReturning` | 目标方法**成功返回**后执行                       |
| **异常通知** | `@AfterThrowing`  | 目标方法**抛出异常**后执行                       |
| **环绕通知** | `@Around`         | 围绕整个方法执行，可控制方法是否执行、修改返回值 |

## 底层实现原理

Spring AOP 的底层主要依靠 **动态代理** 机制。根据目标对象是否实现接口，它会自动切换两种策略：

1. **JDK 动态代理**：
   - **前提**：目标类必须实现至少一个接口。
   - **机制**：通过 `java.lang.reflect.Proxy` 动态创建接口的实现类。
2. **CGLIB 代理**：
   - **前提**：目标类没有实现接口。
   - **机制**：通过继承目标类，并在子类中拦截方法调用（使用 `ASM` 字节码操作）。
   - **限制**：由于是继承，`final` 修饰的类或方法无法被代理。

## 切点表达式（Pointcut Expression）

最常用的是 execution 表达式，格式如下：

execution(modifiers-pattern? ret-type-pattern declaring-type-pattern? name-pattern(param-pattern) throws-pattern?)

- **通配符**：
  - `*`：匹配任意字符，但只能匹配一级路径。
  - `..`：匹配任意字符，可以匹配多级目录（包名）或任意数量的参数。
- **示例**：
  - `execution(* com.example.service.*.*(..))`：匹配 service 包下所有类的所有方法。

## AOP 的执行顺序

当多个切面作用于同一个方法时，默认情况下顺序是不确定的。

- **控制顺序**：可以使用 `@Order(n)` 注解，数字越小优先级越高。
- **入站过程**：优先级高的先执行（`@Before`）。
- **出站过程**：优先级高的后执行（`@After`）。

## AOP失效场景

Spring AOP 失效是开发中非常高频的问题。其核心原因通常可以归结为一句话：**“没有经过代理对象（Proxy）的调用，AOP 统统不生效。”**

### 内部调用（Self-Invocation）—— **最常见原因**

### 修饰符不是 `public`

如果你在 `private`、`protected` 或 `default`（包级私有）方法上添加 AOP 注解，它通常不会生效。

- **原因**：
  - **JDK 动态代理**：要求必须是接口方法，默认只能代理 `public`。
  - **CGLIB 代理**：虽然通过子类实现，但 Spring 默认的事务/缓存拦截器在设计时通常会检查方法修饰符，如果不是 `public` 则跳过。
- **解决方案**：将方法改为 `public`。

### 使用了 `static` 或 `final` 关键字

- **static 方法**：属于类级别，不属于实例，代理对象无法拦截。
- **final 方法**：
  - **CGLIB 代理**是通过继承目标类来创建代理的，`final` 方法无法被子类重写，因此无法织入代码。
  - **JDK 代理**针对接口，通常不涉及 `final` 问题，但在类层面上也无法增强。

### 目标类没有被 Spring 管理

如果你的类没有标注 `@Service`、`@Component` 等注解，或者没有被扫描到，那么它只是一个普通的 Java 对象，而不是 Spring Bean。

- **原因**：Spring AOP 只作用于 **Spring 容器中的 Bean**。如果你手动 `new` 了一个对象，Spring 无法为其生成代理。

### 代理方式配置冲突

如果你依赖 **JDK 动态代理**，但目标类没有实现任何接口，AOP 会失效（除非配置了强制使用 CGLIB）。

- **排查点**：检查是否开启了 `proxy-target-class=true`（SpringBoot 默认开启 CGLIB，但在旧版 Spring 或特定配置下可能需要手动指定）。



## 为什么需要 AOP？（应用场景）

- **声明式事务管理**（Spring 最经典的 AOP 应用）。
- **权限校验**（在执行业务逻辑前检查用户权限）。
- **日志记录**（记录请求参数、耗时、异常日志）。
- **性能统计**（利用 `@Around` 记录方法执行时间）。
- **缓存处理**（如 `@Cacheable` 的底层实现）。
