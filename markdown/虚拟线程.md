# 虚拟线程

**虚拟线程（Virtual Thread）** 是 JDK 21 正式引入的一种**极度轻量级**的线程。

它的核心目标是：**让 Java 能够以简单的“同步阻塞”代码，实现极高的并发量。**

------

### 1. 为什么要引入虚拟线程？

在 JDK 21 之前，Java 线程（称为**平台线程**）与操作系统的**内核线程**是一一对应的（1:1）。

- **昂贵**：创建一个内核线程大约需要 1MB 的内存（栈空间）。
- **有限**：一台普通服务器能支撑的线程数通常只有几千个。
- **低效**：当线程遇到网络 I/O（如等待数据库返回）时，它会被挂起，导致宝贵的内核线程被“白白占用”，造成资源浪费。

为了解决这个问题，以前我们被迫使用 **响应式编程（Reactive Programming）**，但那种代码非常难写、难调试（回调地狱）。

### 2. 虚拟线程的运行原理

虚拟线程采用了 **M:N 调度模型**：成千上万个虚拟线程可以映射到极少数的平台线程上运行。

- **载体线程 (Carrier Thread)**：底层的几个物理/平台线程。
- **挂起不阻塞**：当一个虚拟线程执行到阻塞操作（如 `InputStream.read()`）时，JVM 会自动将该虚拟线程的堆栈保存到堆内存中，并让载体线程去执行其他的虚拟线程。
- **恢复执行**：当 I/O 准备就绪，JVM 重新把之前的堆栈加载回载体线程，从断点处继续运行。

**结果**：对于开发者来说，代码看起来还是阻塞的，但底层却实现了非阻塞的效果。

------

### 3. 核心优势对比

| **特性**     | **平台线程 (Old)** | **虚拟线程 (New)**                        |
| ------------ | ------------------ | ----------------------------------------- |
| **创建成本** | 很高（约 1MB）     | 极低（约几百字节）                        |
| **并发数量** | 数千个就到极限     | **数百万个**没压力                        |
| **切换开销** | 涉及内核态转换，慢 | JVM 内部切换，极快                        |
| **使用方式** | 必须使用线程池复用 | **随用随弃**，无需池化                    |
| **适用场景** | CPU 密集型任务     | **I/O 密集型任务**（Web服务、数据库操作） |

------

### 4. 代码演示

以前我们写高并发代码需要考虑线程池大小：

```Java
// 传统：使用固定大小线程池
var executor = Executors.newFixedThreadPool(100);
```

现在，你可以为每一个请求都创建一个新线程：

```java
// 虚拟线程：为每个任务开启一个新线程，无需池化
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    IntStream.range(0, 10_000).forEach(i -> {
        executor.submit(() -> {
            Thread.sleep(Duration.ofSeconds(1)); // 看起来是阻塞，其实不占资源
            return i;
        });
    });
} // 自动关闭并等待任务结束
```

### 5. 注意事项

1. **不要池化虚拟线程**：虚拟线程很便宜，随用随建。
2. **避免在 `synchronized` 块中执行 I/O**：这会导致虚拟线程“固定”（Pinned）在载体线程上，无法释放资源。建议改用 `ReentrantLock`。
3. **不适合计算密集型**：如果你的代码一直在算素数，不涉及 I/O 切换，虚拟线程反而会因为额外的管理开销比普通线程慢。
