# 红黑树

红黑树（Red-Black Tree）是一种**自平衡二叉查找树**（Self-balancing Binary Search Tree）。它在计算机科学中非常重要, 因为它能保证在最坏情况下，查找、插入和删除操作的时间复杂度均为 $O(\log n)$。

简单来说，它通过在每个节点上增加一个存储位来表示节点的**颜色**（红色或黑色），并通过一套特定的规则来保持树的平衡。

------

### 1. 红黑树的五个性质

为了保持平衡，红黑树必须严格遵守以下五个性质：

1. **节点非红即黑**：每个节点要么是红色，要么是黑色。
2. **根节点是黑色**。
3. **叶子节点（NIL）是黑色**：这里的叶子节点是指为空（NULL）的逻辑末端。
4. **红色节点不能相邻**：即红节点的子节点必须是黑色（不能有两个连续的红节点）。
5. **黑色完美平衡**：从任一节点到其每个叶子的所有路径，都包含相同数目的黑色节点。

------

### 2. 为什么要用红黑树？

你可能会问，既然已经有了**二叉查找树（BST）**，为什么还需要红黑树？

- **防止退化**：普通的二叉查找树在插入有序数据时，可能会退化成一个“链表”，导致查询效率从 $O(\log n)$ 变成 $O(n)$。
- **对比 AVL 树**：AVL 树是另一种平衡树，它要求更加严格的平衡。虽然 AVL 树的查询速度稍快，但红黑树在**插入和删除**操作时的旋转次数更少，整体性能更稳定。

### 3. 如何保持平衡？

当我们在红黑树中插入或删除节点时，可能会破坏上述五个性质。为了修复它，红黑树主要靠两种手段：

- **变色**：将节点的颜色由红变黑，或由黑变红。
- **旋转**：分为**左旋（Left Rotate）\**和\**右旋（Right Rotate）**，通过改变节点的层级结构来重新分配高度。

------

### 4. 实际应用场景

由于其优秀的性能，红黑树在底层开发中无处不在：

- **Java**：`TreeMap` 和 `TreeSet` 的底层实现，以及 JDK 1.8 之后 `HashMap` 的冲突处理（当链表长度超过 8 时转为红黑树）。
- **C++ STL**：`std::map`、`std::set`、`std::multimap` 的底层实现。
- **Linux 内核**：用于进程调度（CFS 调度器）和内存管理。
